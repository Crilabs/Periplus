# M6 Abnahme: Lieferung

Abnahmekriterium aus der Roadmap (Gesamtdesign): Paket des Pilotreviers besteht alle Validierungsregeln und ist per API mit Schlüssel abrufbar. Teil-Spec 08: „Paket des Pilotreviers besteht alle Validierungsregeln; per API mit Schlüssel abrufbar“; „ein Spot zum Stand vor dem Revisit (M7) abrufbar“. Dazu der offene Punkt der Spec: die ODbL-Trennung ist vor der Weitergabe rechtlich zu prüfen; bis dahin werden Pakete nur intern genutzt.
Ablauf: `docs/runbook.md`, Abschnitt „Lieferung“.

**Stand (wie Ruling M4-J-R0):** Die Entwicklungsdatenbank ist leer (0 Geo-Objekte, 0 Orte; Migrationsstand 0037). M6 bringt die Migrationen 0038–0043: vor dem ersten Lauf und vor „Paket bauen“ `npm run db:migrate` (Server: jedes Deployment migriert, `scripts/deploy/deploy.sh`; von Hand `docker compose -f docker/compose.prod.yml --profile migrate run --rm migrate`), danach Migrationsstand **0043**. Alle Messwerte auf echten Daten werden deshalb **im Pilot (M7) gemessen**, nach Gazetteer, Geometrie, Crawl, Text-Läufen und Konsolidierung. M6 baut und prüft jeden Schritt an der Synthetik (Fixture-Revier, `withRollback`, Testdatenbank und Test-Bucket); M6 braucht keinen externen Dienst, für die Umsetzung wurde kein Geld ausgegeben.
